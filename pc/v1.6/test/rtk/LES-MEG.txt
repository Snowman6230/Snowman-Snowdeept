Test av RTK i SNOWMAN (rtkmotor.py) – v1.6.91

Testdata: RTKLIB demo5 test/data/rinex (07590920.05o rover, 30400920.05o base, 07590920.05n baner),
henta frå https://github.com/rtklibexplorer/RTKLIB (BSD-2). Ikkje lagra i repoet – klon/last ned til ./rtklib/.

1. python3 lagrtcm.py 1077     → base.rtcm3 (1006+1019+1077) og rover.rtcm3 (1077)
2. python3 replay.py           → motoren åleine: venta 115/115 RTK FIX, spreiing < 1 cm
3. python3 e2e_kjelder.py      → falsk caster (127.0.0.1:2199) og mottakar (socket://127.0.0.1:7791);
   start SNOWMAN med SNOWMAN_RTK_REFTIME=2005-04-02 SNOWMAN_RTK_NAVFILE=rtklib/test/data/rinex/07590920.05n,
   set COM-port socket://127.0.0.1:7791, caster 127.0.0.1:2199, mountpoint TEST, «RTK i SNOWMAN».

NB: RTKLIB sin 1004-kodar gir ein brøkdels syklus-feil på L2 – bruk 1077 (MSM7) til testfiler.

UBX (u-blox RXM-RAWX + RXM-SFRBX, t.d. ZED-F9P) – v1.6.99
4. python3 lagubx.py           → rover.ubx: same rover som RAWX, banene som GPS LNAV-underrammer (SFRBX).
                                  Kvar bane blir kontrollert med RTKLIB decode_frame før ho blir skriven.
5. python3 testubx.py          → dei fire krava, kvart scenario i eigen prosess (RTKLIB-klokka gjeld heile prosessen):
     1 Demux: ufullstendige rammer (1 byte, tilfeldige bitar, 64 byte, alt i éin), oppstart midt i ei ramme,
       øydelagd ramme, UBX + RTCM + NMEA om kvarandre → alle rammer att, NMEA heil, tom buffer
     2 UBX-rover gir same FIX og same posisjon (≤ 2 mm) som RTCM-rover gjennom same motor
     3 Tid: same epoke (alder 0), base éi epoke seint (alder 30 s, eldre blir ikkje brukt),
       PC-klokke 21 år feil utan ref_time (retta etter GPS-tida frå RAWX)
     4 SFRBX → felles nav: basen utan 1019 og inga BRDC-fil; banene samanlikna felt for felt mot RINEX;
       banar som kom før første RAWX (feil veke frå PC-klokka) blir retta
   Venta: «ALT OK».
6. python3 e2e_ubx.py          → heile SNOWMAN: falsk F9P over TCP (USB-bitar) og falsk caster, utan REFTIME.
   Venta: RTK FIX rekna i SNOWMAN frå «UBX RAWX», banene frå SFRBX, feilsøkaren åtvarar om PC-klokka.

NB: rtklib/ kan vere ei lenkje til ein klon av rtklibexplorer/RTKLIB (berre test/data trengst).

Rekkjefølgje på satellittane (t.d. Emlid RS+: 1002 + 1010 + MSM for andre system per epoke) – v1.6.100
7. python3 lagrtcm.py 1077 (basen) og så python3 testrekkjefolgje.py
                                → roveren som 1002 (berre L1) i to meldingar per epoke, høge satellittnummer først.
                                  Same data køyrt sortert. Venta: likt resultat, RTK FIX (berre L1) og «ALT OK».
                                  Utan sortering i motoren: anna resultat, og i felt «no common satellite».

Opptak frå felt – v1.6.104
8. I SNOWMAN: POST /api/opptak {"sek":300} startar opptak av alt frå mottakaren og casteren.
   GET /api/opptak.zip gir opptaket + status.json (utan passord og brukarnamn).
   python3 spel_opptak.py opptak-….bin [data/brdc/BRDC….rnx] [--detalj] → same utrekning som i felt.

RAIM-FDE – éin satellitt med stor feil – v1.6.113
9. python3 lagrtcm.py 1077 og så python3 testraim.py [raim=0|1]
                                → éin satellitt i roveren får +60 m feil i kodemålinga i epoke 40–79 (som ein dårleg bane).
                                  raim=0: ingen løysing i feilperioden («chi-square error»). raim=1 (standard): satellitten
                                  blir kasta ut, FIX heile perioden. Venta: «ALT OK».
